# NoteFlow — инструкции для Codex

## 1. Источники истины

Перед любой задачей обязательно изучить:

1. `docs/reference/NoteFlow_готовый_макет.html`
2. `docs/specifications/product-spec.md`
3. `docs/specifications/NoteFlow_Техническое_задание.docx`
4. `docs/user-guide/NoteFlow_Руководство_пользователя.docx`

При противоречиях:

- по дизайну, расположению элементов, составу экранов и UX-поведению приоритет имеет `docs/reference/NoteFlow_готовый_макет.html`;
- по функциональности, архитектуре, безопасности, производительности и платформам приоритет имеет `docs/specifications/product-spec.md`;
- старые макеты, изображения, HTML-версии и документы использовать запрещено.

## 2. Назначение проекта

NoteFlow — локальное desktop-приложение для заметок с поддержкой Markdown, проектов, тегов, поиска, архива, подключения локальных и публичных LLM, ИИ-чата по текущей заметке и RAG-чата по всей базе.

Обязательные платформы:

- Windows 10/11;
- macOS Apple Silicon;
- macOS Intel, если зависимости сохраняют поддержку.

## 3. Технологический стек

Использовать:

- Tauri 2;
- Rust;
- React;
- TypeScript в строгом режиме;
- Vite;
- TipTap / ProseMirror;
- SQLite;
- SQLite FTS5;
- локальный векторный индекс для RAG.

Не заменять стек без предварительного согласования.

## 4. Основные принципы

- local-first;
- обязательная работа без интернета, кроме внешних ИИ-моделей;
- отсутствие обязательной регистрации;
- локальный профиль пользователя;
- русский язык по умолчанию;
- возможность переключения на английский;
- светлая, тёмная и системная темы;
- высокая скорость и плавность;
- автоматическое сохранение;
- экспорт данных;
- одинаковая функциональность Windows и macOS.

## 5. Интерфейс

Не изменять визуальную концепцию актуального HTML-макета.

Обязательные элементы:

- основной складывающийся сайдбар;
- регулируемая ширина основного сайдбара;
- регулируемая панель списка заметок;
- регулируемый правый чат;
- единая лента форматирования только над редактором;
- все кнопки форматирования в одну строку без горизонтального скролла при стандартной ширине;
- подсказки при наведении;
- режим фокуса с сохранением ленты форматирования;
- кнопка «Новая заметка» в основном сайдбаре;
- создание заметки с названием и датой;
- поиск в панели списка без отдельного модального окна;
- чат по текущей заметке должен сдвигать редактор, а не перекрывать его.

## 6. Разделы приложения

Использовать только разделы, предусмотренные актуальным макетом:

- Все заметки;
- Проекты;
- ИИ-чат по базе;
- Теги;
- Архив;
- Настройки.

Не добавлять новые разделы без согласования.

## 7. Markdown

Редактор должен:

- распознавать Markdown при вставке;
- показывать его в человекочитаемом WYSIWYG-виде;
- сохранять возможность экспорта в Markdown;
- поддерживать заголовки, списки, чек-листы, цитаты, ссылки, таблицы, код, изображения и разделители;
- не терять Markdown-семантику после визуального редактирования.

## 8. ИИ

Поддерживать:

- OpenAI-compatible API;
- Ollama;
- LM Studio;
- пользовательские endpoints;
- локальные и публичные модели.

ИИ работает в двух режимах:

1. чат по текущей заметке;
2. отдельный RAG-чат по всей базе со ссылками на источники.

API-ключи нельзя хранить в исходном коде, Git или обычном localStorage.

## 9. Правила изменения кода

Перед началом задачи:

1. изучить существующий код;
2. проверить `git status`;
3. прочитать относящиеся к задаче документы;
4. для крупной задачи сначала предложить план.

Во время работы:

- не переписывать работающие модули без необходимости;
- не добавлять production-зависимости без объяснения;
- не использовать `any`, кроме явно обоснованных случаев;
- разделять UI, бизнес-логику и слой данных;
- не создавать один огромный React-компонент;
- не добавлять функциональность, которой нет в спецификации;
- не менять дизайн без явного запроса пользователя.

## 10. Проверка после изменений

После каждой задачи выполнить доступные проверки:

```bash
npm run build
```

После настройки соответствующих скриптов также выполнять:

```bash
npm run typecheck
npm run lint
npm run test
```

При изменениях Rust:

```bash
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
```

Не заявлять об успешной проверке, если команда не выполнялась или завершилась ошибкой.

## 11. Формат отчёта Codex

После выполнения задачи сообщить:

1. что изменено;
2. какие файлы изменены;
3. какие команды проверки выполнены;
4. результаты проверок;
5. известные ограничения;
6. рекомендуемый следующий этап.

## 12. Текущий этап

Сейчас проект находится на этапе первоначальной подготовки.

Первой задачей должен быть только каркас интерфейса:

- перенос актуального HTML-макета в React-компоненты;
- основной layout;
- навигация;
- складывание и регулировка панелей;
- страницы из актуального макета;
- светлая и тёмная темы;
- сохранение размеров панелей и темы.

На первом этапе не реализовывать:

- SQLite;
- TipTap;
- реальное сохранение заметок;
- подключение LLM;
- RAG;
- импорт и экспорт;
- синхронизацию.
