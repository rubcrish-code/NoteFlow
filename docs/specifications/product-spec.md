## 2. Цель проекта

NoteFlow — локальное desktop-приложение для хранения, редактирования, поиска и систематизации заметок.

Приложение должно быть быстрым, плавным, минималистичным, полностью на русском языке по умолчанию и работать локально без обязательной регистрации.

Ключевая идея: пользователь пишет заметки, использует Markdown, теги, проекты, поиск и ИИ-помощника. ИИ должен работать как по отдельной заметке, так и по всей базе заметок через RAG.

---

## 3. Платформы

Приложение обязательно должно работать на:

- Windows 10/11 x64;
- macOS 12+;
- macOS Apple Silicon;
- macOS Intel, если используемые зависимости сохраняют поддержку.

Функциональность на Windows и macOS должна быть одинаковой.

Горячие клавиши должны учитывать платформу:

- Windows: `Ctrl`;
- macOS: `Command`.

## 4. Технологический стек

Рекомендуемый стек production-версии:

- Tauri 2;
- Rust;
- React;
- TypeScript strict;
- Vite;
- TipTap / ProseMirror для редактора;
- SQLite для локальной базы;
- SQLite FTS5 для полнотекстового поиска;
- локальный векторный индекс для RAG;
- OpenAI-compatible provider layer для подключения моделей.

Запрещено без согласования:

- заменять Tauri на Electron;
- заменять React на другой UI-фреймворк;
- добавлять тяжёлые UI-библиотеки, которые ломают стиль текущего макета;
- хранить API-ключи в localStorage, исходном коде или Git.

## 6. Локальный профиль

Обязательной регистрации и облачного аккаунта не должно быть.

При первом запуске пользователь создаёт локальный профиль:

- имя;
- инициалы или аватар;
- название локального рабочего пространства;
- папка хранения данных;
- язык интерфейса;
- тема приложения.

Кнопка профиля нужна не для авторизации, а для локального управления:

- изменение имени;
- изменение аватара;
- просмотр расположения базы;
- экспорт и резервное копирование;
- смена локального рабочего пространства;
- блокировка приложения PIN-кодом в будущей версии, если будет согласовано.

## 7. Основные разделы приложения

Состав разделов должен соответствовать актуальному HTML-макету.

### 7.1. Все заметки

Основной рабочий раздел.

Функции:

- просмотр всех активных заметок;
- создание новой заметки;
- поиск по заметкам и тегам;
- выбор заметки из списка;
- редактирование заметки;
- работа с тегами заметки;
- запуск ИИ-чата по текущей заметке;
- вход в режим фокуса;
- форматирование текста;
- работа с Markdown.

### 7.2. Проекты

Раздел для группировки заметок по проектам.

Проект должен содержать:

- название;
- описание;
- список связанных заметок;
- список задач;
- теги;
- дату создания;
- дату обновления;
- статус;
- архивность.

### 7.3. ИИ-чат по базе

Отдельный раздел для общения с ИИ по всей базе заметок.

Функции:

- вопрос по всей базе;
- вопрос по выбранному проекту;
- вопрос по тегу;
- ответ с источниками;
- переход к конкретной заметке-источнику;
- отображение использованных фрагментов;
- уточняющие вопросы.

### 7.4. Теги

Отдельный раздел управления тегами.

Пользователь должен уметь:

- создавать тег;
- переименовывать тег;
- менять цвет тега;
- удалять тег;
- объединять несколько тегов;
- искать теги;
- смотреть количество заметок по тегу;
- открывать список заметок по тегу;
- массово назначать тег заметкам;
- массово удалять тег из заметок.

Удаление тега не должно удалять сами заметки.

### 7.5. Архив

Раздел для заметок, которые не нужны в активной работе, но должны сохраниться.

Функции:

- просмотр архивных заметок;
- поиск по архиву;
- восстановление заметки;
- окончательное удаление только после подтверждения;
- фильтрация по тегам и проектам.

### 7.6. Настройки

Раздел системных настроек приложения.

Обязательные подразделы:

- Основные;
- Внешний вид;
- Модели ИИ;
- Данные и экспорт;
- Горячие клавиши;
- О приложении.

Выбор темы должен находиться только в подразделе `Внешний вид`.

## 8. Интерфейс и layout

Интерфейс строится из трёх основных областей:

1. Левый основной сайдбар.
2. Панель списка заметок.
3. Область редактора.

Дополнительно может открываться правый чат по текущей заметке.

### 8.1. Левый сайдбар

Сайдбар содержит:

- логотип NoteFlow;
- кнопку сворачивания;
- кнопку `Новая заметка`;
- разделы навигации;
- блок профиля пользователя.

Состояния:

- раскрытый;
- компактный;
- скрытый в режиме фокуса.

Ширина сайдбара должна регулироваться пользователем и сохраняться между запусками.

### 8.2. Панель списка заметок

Панель содержит:

- поиск по заметкам и тегам;
- заголовок текущего списка;
- количество элементов;
- карточки заметок.

Панель должна регулироваться по ширине, скрываться при необходимости и не перекрывать редактор.

### 8.3. Область редактора

Редактор содержит:

- хлебные крошки или указание проекта;
- статус сохранения;
- кнопку `Чат по заметке`;
- кнопку режима фокуса;
- меню заметки;
- ленту форматирования;
- заголовок заметки;
- теги заметки;
- тело заметки;
- нижнюю строку состояния.

### 8.4. Правая панель чата

Чат по текущей заметке открывается справа.

Обязательное поведение:

- чат не перекрывает текст заметки;
- при открытии чата редактор сдвигается и сужается;
- ширина чата регулируется пользователем;
- чат можно закрыть;
- ширина чата сохраняется.

## 9. Создание заметки

Кнопка создания заметки находится в основном сайдбаре.

При нажатии открывается окно создания заметки.

Пользователь указывает:

- название заметки;
- дату заметки.

После создания:

- заметка появляется в списке;
- открывается редактор;
- курсор устанавливается в тело заметки или заголовок;
- заметка получает статус `Сохранено` после автосохранения;
- дата отображается в карточке и метаданных.

Горячая клавиша:

- Windows: `Ctrl + N`;
- macOS: `Command + N`.

## 10. Markdown

Markdown — ключевая функция приложения.

Редактор должен поддерживать вставку Markdown-текста и автоматическое преобразование в человекочитаемый WYSIWYG-вид.

Обязательно поддержать:

- `# Заголовок 1`;
- `## Заголовок 2`;
- `### Заголовок 3`;
- жирный текст;
- курсив;
- подчёркивание, если поддерживается редактором;
- зачёркивание;
- маркированные списки;
- нумерованные списки;
- чек-листы;
- цитаты;
- ссылки;
- изображения;
- таблицы;
- inline code;
- code block;
- горизонтальный разделитель;
- выноски / callout-блоки;
- сворачиваемые блоки.

Если пользователь вставляет Markdown, редактор должен автоматически распознать его и показать визуальное форматирование. Пользователь не должен нажимать отдельную кнопку `Распознать Markdown`.

Внутренний формат может быть JSON-документом TipTap/ProseMirror, но приложение должно уметь:

- экспортировать заметку в Markdown;
- импортировать Markdown;
- не терять семантику Markdown после редактирования;
- корректно обрабатывать таблицы, списки и код.

## 14. Работа с ИИ

ИИ работает в двух режимах:

1. Чат по текущей заметке.
2. Общий ИИ-чат по всей базе через RAG.

### 14.1. Чат по текущей заметке

Открывается кнопкой `Чат по заметке`.

Контекст:

- текущая заметка;
- выделенный фрагмент, если пользователь выделил текст;
- метаданные заметки;
- теги;
- проект.

Примеры действий:

- пересказать заметку;
- найти задачи;
- исправить текст;
- сделать текст официальнее;
- сократить;
- расширить;
- продолжить мысль;
- объяснить простыми словами;
- найти противоречия;
- предложить структуру;
- выделить решения;
- подготовить резюме.

Ответ ИИ не должен автоматически заменять текст. Пользователь выбирает действие:

- вставить;
- заменить выделенный фрагмент;
- вставить ниже;
- скопировать;
- отменить.

### 14.2. Общий ИИ-чат по базе

Раздел `ИИ-чат по базе`.

Пользователь может задавать вопросы:

- по всей базе;
- по проекту;
- по тегу;
- по выбранным заметкам;
- за период времени.

Ответ должен содержать источники:

- название заметки;
- фрагмент;
- переход к месту в заметке;
- дата заметки;
- релевантность, если возможно.

## 16. RAG

RAG строится по локальной базе заметок.

Процесс:

1. Заметка создаётся или изменяется.
2. Текст преобразуется в индексируемый вид.
3. Текст разбивается на смысловые фрагменты.
4. Для фрагментов создаются embeddings.
5. Фрагменты сохраняются в локальный индекс.
6. Пользователь задаёт вопрос.
7. Выполняется гибридный поиск.
8. Релевантные фрагменты отправляются в LLM.
9. ИИ возвращает ответ.
10. Пользователь видит ответ и источники.

Поиск должен быть гибридным:

- полнотекстовый поиск;
- векторный поиск;
- фильтры;
- реранжирование, если будет реализовано.

## 21. Производительность

Целевые показатели:

- запуск приложения: до 2 секунд после прогрева;
- открытие заметки: до 150 мс для обычной заметки;
- ввод текста: без заметных лагов;
- поиск: до 300 мс на базе до 10 000 заметок;
- переключение разделов: до 200 мс;
- открытие чата по заметке: до 250 мс без генерации ответа;
- автосохранение: без блокировки интерфейса.

Требования:

- не перерисовывать весь интерфейс при каждом вводе символа;
- изолировать редактор от лишних React-рендеров;
- тяжёлые операции выполнять асинхронно;
- индексацию выполнять в фоне;
- не блокировать UI при RAG и embeddings.

---

## 22. Безопасность

Обязательные требования:

- API-ключи не хранятся в открытом виде;
- локальная база не отправляется во внешние сервисы без действия пользователя;
- при использовании публичной LLM пользователь видит предупреждение, что данные отправляются внешнему провайдеру;
- при локальных моделях через Ollama/LM Studio данные остаются на компьютере, если endpoint локальный;
- экспорт не включает API-ключи;
- логи не содержат секреты;
- сетевые запросы к LLM прозрачны и настраиваемы.

---

## 23. Оффлайн-режим

Без интернета должны работать:

- запуск приложения;
- просмотр заметок;
- редактирование;
- поиск;
- теги;
- проекты;
- архив;
- экспорт локальных данных;
- локальная модель, если она доступна через локальный endpoint.

Без интернета не работают:

- публичные LLM API;
- загрузка внешних изображений, если они не сохранены локально;
- проверка обновлений, если будет реализована.

## 24. Критерии приёмки MVP

MVP считается готовым, если:

1. Приложение запускается на Windows и macOS.
2. Интерфейс соответствует актуальному HTML-макету.
3. Есть разделы: Все заметки, Проекты, ИИ-чат по базе, Теги, Архив, Настройки.
4. Работает создание заметки с названием и датой.
5. Работает редактирование заметки.
6. Работает вставка Markdown с преобразованием в WYSIWYG.
7. Работают основные инструменты форматирования.
8. Работает поиск по названию, тексту и тегам.
9. Работает управление тегами.
10. Работают проекты.
11. Работает архивирование и восстановление.
12. Работают светлая и тёмная темы.
13. Работает режим фокуса с лентой форматирования.
14. Работает регулируемая ширина сайдбара и списка.
15. Работает правый чат по заметке без перекрытия редактора.
16. Есть настройки подключения LLM.
17. Есть общий ИИ-чат по базе с источниками.
18. Есть экспорт заметок и всей базы.
19. API-ключи хранятся безопасно.
20. Приложение работает быстро и не зависает при обычном использовании.

```bash
npm run typecheck
npm run lint
npm run test
npm run build
```

Если скриптов ещё нет — добавить их на раннем этапе.

Для Rust:

```bash
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
```
