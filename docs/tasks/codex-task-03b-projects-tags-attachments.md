# NoteFlow — задача 03B. Проекты, теги, архив и вложения

Начинать после завершения SQLite-задачи 03A.
Перед началом прочитать `AGENTS.md`, актуальный HTML-макет и `product-spec.md`.
Git commit не выполнять.

## Цель

Перевести проекты, теги, архив, меню заметки и локальные вложения с mock/in-memory на реальное локальное хранение.

## Реализовать

1. SQLite-таблицы и миграции:
   - projects;
   - tags;
   - note_tags;
   - attachments;
   - при необходимости project_notes;
   - индексы и внешние ключи.

2. Проекты:
   - создание;
   - изменение;
   - архивирование;
   - удаление с подтверждением;
   - цвет проекта;
   - привязка заметки к проекту;
   - сохранение после перезапуска.

3. Теги:
   - создание;
   - переименование;
   - удаление;
   - палитра минимум 24 цвета;
   - HEX-ввод;
   - объединение тегов;
   - массовое назначение и снятие;
   - удаление тега не удаляет заметки.

4. Архив:
   - архивировать;
   - восстановить;
   - окончательно удалить с подтверждением;
   - корректно очистить связи.

5. Меню заметки:
   - дублировать;
   - избранное;
   - переместить в проект;
   - архивировать;
   - удалить;
   - все операции через SQLite.

6. Локальные изображения и файлы:
   - системный диалог Tauri;
   - копирование в managed storage;
   - метаданные в SQLite;
   - безопасные относительные ссылки;
   - открытие системным приложением;
   - удаление с подтверждением;
   - защита от path traversal.

7. Экспорт одной заметки:
   - Markdown;
   - вложения рядом или в ZIP;
   - без секретов.

## Проверки

- TypeScript tests/build;
- Rust fmt/clippy/tests;
- сохранение после перезапуска;
- Windows;
- корректные пути для macOS.

В отчёте указать схему БД, Tauri commands, расположение вложений и ограничения.
