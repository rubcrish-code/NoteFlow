# NoteFlow — задача 02C. Доработка редактора и критические UI-исправления

Перед началом обязательно прочитать:

- `AGENTS.md`
- `docs/reference/NoteFlow_готовый_макет.html`
- `docs/specifications/product-spec.md`
- текущую реализацию TipTap/Markdown

Git commit самостоятельно не выполнять.

## Цель

Исправить текущие дефекты редактора и интерфейса, довести все заявленные инструменты до рабочего состояния и сохранить актуальный дизайн NoteFlow.

## 1. Превью заметки в списке

Сейчас в карточке заметки появляются HTML/Markdown-маркеры и служебные символы.

Исправить:

- формировать превью только из `plainText`;
- полностью удалять HTML-теги, Markdown-маркеры, служебные символы и лишние пробелы;
- не показывать `</u>`, `**`, `#`, теги и фрагменты сериализации;
- ограничивать длину аккуратно;
- корректно добавлять многоточие;
- добавить тесты для HTML, Markdown, таблиц, списков и подчёркивания.

## 2. Подсветка и цвет текста

Исправить toggle-поведение:

- повторное нажатие на активную подсветку снимает подсветку;
- повторный выбор текущего цвета текста сбрасывает цвет к автоматическому;
- добавить явные действия `Без подсветки` и `Автоматический цвет`;
- расширить обе палитры минимум до 20–24 спокойных цветов;
- добавить дополнительную строку цветов;
- палитры должны корректно выглядеть в светлой и тёмной темах;
- active-состояние должно соответствовать реальному состоянию TipTap.

## 3. Критическое исправление режима фокуса

Сейчас надпись/кнопка выхода перекрывает панель форматирования.

Исправить обязательно:

- полностью убрать absolute/fixed-позиционирование поверх toolbar;
- разместить кнопку выхода в отдельной верхней строке layout либо справа в существующей строке, но не поверх инструментов;
- toolbar должен оставаться полностью доступным;
- ни одна кнопка не должна перекрываться;
- проверить ширины 1100, 1440 и 1920 px;
- выход работает кнопкой и `Esc`;
- добавить regression-тест или layout-проверку, чтобы перекрытие не вернулось.

## 4. Выноска

Реализовать рабочий TipTap-блок callout.

Поддержать варианты:

- информация;
- совет;
- предупреждение;
- важно.

Требования:

- иконка;
- фон;
- рамка;
- редактируемый текст;
- светлая/тёмная тема;
- сериализация и повторная загрузка в JSON/HTML/Markdown.

## 5. Сворачиваемый блок

Реализовать рабочий TipTap-блок details/summary:

- редактируемый заголовок;
- сворачиваемое содержимое;
- открытое/закрытое состояние;
- корректная работа в обеих темах;
- сериализация и повторная загрузка.

## 6. Меню «Вставить блок»

Сделать рабочее меню вставки блоков.

Пункты:

- абзац;
- H1/H2/H3;
- маркированный список;
- нумерованный список;
- чек-лист;
- цитата;
- код;
- таблица;
- выноска;
- сворачиваемый блок;
- изображение;
- файл;
- дата;
- формула.

Меню:

- не выходит за границы окна;
- закрывается по клику вне и `Esc`;
- сохраняет selection редактора.

## 7. Локальные изображения и файлы

Не использовать URL как основной сценарий.

Изображения:

- выбор с локального устройства через Tauri dialog;
- копирование в управляемую папку данных NoteFlow;
- вставка в редактор;
- корректное отображение после перезапуска.

Файлы:

- выбор с локального устройства;
- копирование в managed storage;
- карточка файла в редакторе;
- имя, размер, тип;
- открыть системным приложением;
- удалить с подтверждением.

На текущем этапе допустимо подготовить storage abstraction, если реальное хранение будет окончательно подключено вместе с SQLite, но UI выбора локального файла должен быть рабочим и архитектура не должна сохранять абсолютные пути пользователя в документе.

## 8. Упоминания

Реализовать локальные упоминания заметок через `@`:

- поиск среди заметок;
- красивый inline-chip;
- клик открывает связанную заметку;
- пользователей пока не добавлять;
- сериализация и повторная загрузка.

## 9. Даты

Реализовать вставку даты:

- date picker в стиле NoteFlow;
- inline-date node/mark;
- формат отображения `ДД.ММ.ГГГГ`;
- хранить нормализованное значение;
- корректная сериализация.

## 10. Формулы

Реализовать:

- inline formula;
- block formula;
- LaTeX-ввод;
- визуальный рендер;
- сериализацию и повторную загрузку;
- объяснить выбранную лёгкую зависимость.

## 11. Кнопка ИИ

Пока реального LLM нет, но кнопка должна быть полезной:

- открывать меню AI-действий;
- если провайдер не настроен — показывать понятное состояние и кнопку перехода в `Настройки → Модели ИИ`;
- не имитировать ложный ответ;
- подготовить интерфейс команд для следующего AI-этапа.

## 12. Меню заметки

Сделать рабочим:

- переименовать;
- дублировать;
- добавить/убрать из избранного;
- переместить в проект;
- архивировать;
- удалить с подтверждением;
- экспорт Markdown — можно подключить, если сервис уже готов.

Пока данные могут оставаться in-memory, если SQLite ещё не реализован, но действия должны реально менять текущее состояние.

## 13. Создание проекта

Добавить кнопку `Новый проект`.

Модалка:

- название;
- описание;
- цвет;
- создание проекта в in-memory state;
- новый проект сразу появляется в списке;
- расширенная палитра цветов.

## 14. ИИ-чат по базе

Доделать layout:

- левый основной сайдбар регулируется;
- список диалогов регулируется по ширине;
- дополнительная панель источников, если есть, тоже регулируется;
- размеры сохраняются в localStorage;
- основной чат занимает оставшееся место;
- нет пустых зон, обрезания и сдвига вправо;
- корректно работает при 1100×700, 1440×900 и 1920×1080.

Реальные LLM/RAG-запросы пока не реализовывать в этой задаче.

## 15. Теги

Расширить палитру тегов:

- минимум 24 цвета;
- спокойные оттенки;
- поддержка светлой и тёмной темы;
- HEX-ввод;
- корректный контраст текста на цветном фоне;
- предпросмотр.
