# NoteFlow — задача 02E. Финальная стилизация выбора шрифта и подготовка preview-сборки

Перед началом обязательно прочитать:

- `AGENTS.md`
- `docs/reference/NoteFlow_готовый_макет.html`
- `docs/specifications/product-spec.md`
- текущую реализацию toolbar и popover выбора шрифта

Git commit самостоятельно не выполнять.

## Цель

Исправить критическое визуальное несоответствие элементов выбора шрифта, размера и кнопок отмены/сброса. После этого подготовить устанавливаемую preview-сборку NoteFlow для Windows.

Важно: не менять общую концепцию актуального HTML-макета.

## 1. Выбор шрифта

Текущий контрол не вписывается в дизайн.

Исправить:

- убрать внешний вид нативного `select`;
- использовать одну компактную кнопку-триггер в toolbar, например `Aa`;
- высота, радиус, отступы, иконка, границы и hover должны совпадать с остальными кнопками toolbar;
- не делать кнопку визуально крупнее соседних инструментов;
- выбранный шрифт отображать внутри popover, а не длинной надписью в toolbar;
- popover должен быть скруглённым, лёгким, минималистичным и соответствовать актуальному макету;
- варианты шрифтов показывать реальным начертанием;
- активный вариант отмечать аккуратной галочкой или подсветкой;
- поддержать светлую и тёмную темы;
- не использовать случайные системные стили браузера.

## 2. Размер текста

Исправить контрол размера:

- не использовать отдельный крупный нативный select;
- разместить размеры в том же popover `Aa`;
- показывать компактный список или сетку размеров;
- размеры: 12, 14, 16, 18, 20, 24, 28, 32, 36;
- текущее значение выделять;
- применять размер без потери выделения редактора;
- визуально соблюдать те же токены, что и у остальных popover NoteFlow.

## 3. Кнопки отмены и сброса

Все кнопки отмены/сброса в popover должны соответствовать дизайну приложения:

- никаких стандартных HTML-кнопок;
- высота, радиус и типографика как у остальных secondary-кнопок NoteFlow;
- `Отмена` — спокойная вторичная кнопка;
- `Сбросить` — текстовая или вторичная кнопка без агрессивного красного цвета;
- `Применить` — основная акцентная кнопка;
- кнопки не должны быть слишком большими;
- кнопки должны корректно выглядеть в тёмной теме.

Если речь идёт о toolbar-кнопках undo/redo:

- привести их размер, hover, active и tooltip к остальным кнопкам toolbar;
- не выделять их отдельными тяжёлыми рамками.

## 4. Компоновка toolbar

Проверить после изменений:

- toolbar остаётся в одну строку;
- нет горизонтального скролла при 1440×900;
- кнопка `Aa` не ломает интервалы;
- tooltip не обрезается;
- режим фокуса не перекрывает toolbar;
- элементы корректно выглядят при 1100×700 и 1920×1080.

## 5. Критерии визуальной приёмки

Результат должен выглядеть как часть NoteFlow, а не как сторонний web-компонент:

- те же радиусы;
- те же серые и синие оттенки;
- те же тени;
- одинаковая высота элементов;
- спокойные hover/active состояния;
- отсутствие нативных браузерных select/button;
- полная поддержка тёмной темы.

## 6. Исправить известный тест

Исправить `createNotePreview`, чтобы не оставались пробелы перед знаками препинания.

Ожидается:

```text
Заголовок Текст с жирным, курсивом и кодом.
```

Добавить/обновить тесты для:

- запятых и точек;
- скобок;
- кавычек;
- повторных пробелов.

## 7. Проверки

Выполнить:

```bash
npm run typecheck
npm run test
npm run build
npm run tauri dev
```

Убедиться:

- все тесты проходят;
- приложение запускается;
- нет ошибок в консоли;
- новые контролы выглядят корректно в светлой и тёмной теме.

## 8. Preview-сборка Windows

После успешных проверок подготовить устанавливаемую preview-сборку:

```bash
npm run tauri build
```

Перед сборкой проверить в `src-tauri/tauri.conf.json`:

- productName: NoteFlow;
- version в формате semver;
- identifier;
- корректные иконки;
- bundle.active: true;
- Windows targets: `nsis` и/или `msi`;
- название окна;
- минимальный и стартовый размер окна.

Не включать dev-файлы и секреты.

В отчёте указать:

1. что изменено в дизайне;
2. какие файлы изменены;
3. результаты тестов;
4. результаты build;
5. путь к `.exe`/`.msi`;
6. известные ограничения preview-версии.
