# NoteFlow — замена иконки приложения

Перед началом прочитать:

- `AGENTS.md`
- `docs/reference/NoteFlow_готовый_макет.html`
- `docs/reference/NoteFlow_app_icon_reference.png`
- текущую реализацию логотипа внутри основного сайдбара

Git commit самостоятельно не выполнять.

## Цель

Заменить стандартную иконку Tauri у desktop-приложения, установщика и ярлыков на фирменный логотип NoteFlow, который уже используется внутри приложения:

- синий скруглённый квадрат;
- белая восходящая ломаная линия;
- визуально точно соответствует внутреннему логотипу NoteFlow.

Приложенный PNG использовать как визуальный референс. Не использовать маленький скриншот напрямую как production-иконку.

## 1. Единый исходник логотипа

Найти текущий внутренний логотип в React/CSS/SVG.

На его основе создать один чистый master-файл:

```text
src-tauri/icons/noteflow-icon-source.png
```

Требования к master-файлу:

- квадрат 1024×1024;
- прозрачный фон за пределами синего квадрата;
- синий скруглённый квадрат занимает большую часть площади;
- белая линия центрирована и имеет достаточную толщину;
- правильные внутренние отступы;
- без текста;
- без белого прямоугольного фона;
- хорошо читается в размерах 16×16, 32×32 и 48×48;
- визуально совпадает с логотипом внутри приложения.

Предпочтительно использовать исходный SVG/React path внутреннего логотипа, а не рисовать приблизительную копию со скриншота.

## 2. Генерация платформенных иконок

Использовать официальный генератор Tauri:

```bash
npm run tauri icon src-tauri/icons/noteflow-icon-source.png
```

Команда должна обновить комплект иконок в `src-tauri/icons`, включая форматы Windows и macOS.

Проверить `src-tauri/tauri.conf.json`:

- bundle использует новые иконки;
- нет ссылок на старые стандартные иконки Tauri;
- иконка окна также использует фирменный набор, где это требуется.

## 3. Где иконка должна измениться

Проверить после сборки:

- верхний левый угол окна NoteFlow;
- панель задач Windows;
- Alt+Tab;
- файл `noteflow.exe`;
- NSIS installer;
- MSI installer;
- ярлык меню «Пуск»;
- ярлык рабочего стола, если создаётся;
- список установленных приложений Windows;
- будущий комплект `.icns` для macOS.

Внутренний логотип в сайдбаре и внешняя иконка приложения должны выглядеть одинаково.

## 4. Кэш и версия сборки

Windows может кэшировать старую иконку.

Для проверки:

- удалить ранее установленную preview-версию;
- удалить старые ярлыки;
- собрать новую версию;
- установить её заново;
- при необходимости увеличить patch/prerelease-версию, чтобы установщик корректно обновился;
- не менять identifier без отдельного согласования, кроме уже запланированного исправления окончания `.app`.

Не удалять пользовательские данные без необходимости.

## 5. Проверки

Выполнить:

```bash
npm run typecheck
npm run test
npm run build
npm run tauri build
```

Проверить иконки вручную минимум в размерах:

- 16×16;
- 32×32;
- 48×48;
- 128×128;
- 256×256.

Убедиться:

- линия не размыта;
- края синего квадрата аккуратные;
- нет белого фона;
- иконка не слишком мелкая;
- иконка не обрезана;
- новая иконка видна в установщике и после установки.

## 6. Итоговый отчёт

Сообщить:

1. откуда взят исходный path/asset внутреннего логотипа;
2. какие icon-файлы были сгенерированы;
3. какие конфиги изменены;
4. результаты тестов и сборки;
5. пути к новому NSIS/MSI;
6. где иконка была проверена вручную;
7. известные особенности кэша Windows.
